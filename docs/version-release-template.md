# 版本发布说明模板

发布前把每项填写为具体行为、契约身份或验证证据；不适用时写明原因。

## 版本与行为

- 版本、完整提交 SHA、前一发布/PR 基线提交：
- 可观察行为变化、触发条件及使用示例：
- 缺省行为和需要显式开启的选项：
- 仍缺少的能力、不能完成的操作和未经硬件验证的结论：

## 消费者与契约

- 新增、保留、替代或退役的契约身份及各自消费者：
- 源契约组合 → 目标契约组合、registry 升级边 ID 与选择路径：
- 旧格式读取、目标写入、校验器和外部消费者所需版本：
- capability/consumer 减少时的 `CONTRACT_TRANSITIONS` 声明、原因、验收矩阵行：
- 独立新增且没有迁移前身的契约及原因：

## 历史证明与运行交接

- 固定历史 ZIP、expected JSON 路径和 SHA256；不得重生成旧 fixture：
- `release_acceptance` 中的实际 pytest 节点、通过结果和 CI 链接：
- 历史身份、文件字节、原输入/修订、审核、release、任务、attempt 与失败证据的保留结果：
- 来源变更、产物缺失、目标冲突、回退路径和反向条件验证结果：
- 外部 hold、活动 worker、存储目标和恢复所需的显式交接：
- 回退/恢复是否可逆，需要保留的原归档与备份，以及适用范围：

## 成本与剩余验收

- 下载、ASR、AI 的实际调用次数；需要昂贵补算时列明输入、配置、范围、成本和单独授权入口：
- 测试环境、真实模型/硬件与替身的区别；性能、质量、峰值资源的测量口径：
- 已知限制、后续验收、负责 issue：

收集门禁只证明所登记测试仍参与测试集；成功发布还要求四个分片实际通过。
兼容路径已登记也不代表原始运行环境可以自动切换、恢复任务或清除 hold。
