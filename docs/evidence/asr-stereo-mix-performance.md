# ASR 双声道混音优化

2026-10-11 的生产机器隔离实验已足以支持实现一个范围明确的优化：以 float32 双声道逐项相加和缩放替代逐行 `mean`，减少整段音频准备中的 CPU 开销。该改动已经进入独立分支 `codex/asr-stereo-mix-performance`，基于 `608aeaba8afe1223e1e6a4a4d4225c6183a907dd`。不需要为实现这个分支重复停止生产 worker。

## 实现与输入行为

`asr.audio._mono_float32` 统一 runner 和分块器的单声道转换：

- 先维持原有 float32 转换，再为 `(samples, 2)` 输入使用专用分支。
- 只创建一个单声道结果数组，声道相加、零符号处理和乘 0.5 共用该输出；不原地修改解码器返回的输入。
- 保留原 `mean` 的零符号规则：两路 `-0.0` 的归约结果为 `+0.0`。加正零发生在缩放前，负的极小值缩放后仍可正确得到 `-0.0`。
- mono float32 输入直接复用；其他声道数和维度保留原 `mean` 路径。只读、倒序、跨步及 Fortran 布局输入也可处理。

解码、声道读取、soxr 重采样、分块边界及生成/对齐参数沿用原路径。优化没有增加后台线程、生产队列预领、配置项或依赖，也没有改动已有任务和转录。完整音频解码数组的内存成本仍然存在；这项改动不构成内存预算机制。

## 为什么选这个范围

此前在生产 RTX 4090 上进行了 15 波双 worker 固定输入实验，每方案 3 次。每波处理 2004.061 秒音频，以两个常驻、预热后的 worker 的共同墙钟计算吞吐；以下是相对同轮基线的变化中位数。

| 方案 | 吞吐变化 | 实现决策 |
|---|---:|---|
| 双声道直接相加 | +0.43% | 局部 CPU 成本明确，先实施 |
| 深度 1 音频准备预取 | +1.10% | 涉及任务所有权、取消和预算；本分支不实现 |
| 深度 1 对齐并行 | −0.20% | 三轮均慢于对应基线；本分支不实现 |
| 已准备波形对照 | +1.13% | 排除了准备成本，仅作对照 |

60 次转录中的首轮 4 次建立参考，其余 56 次的文本、时间戳、字级结果、覆盖率、质量标记及逐块结果全部一致；完整结果随后独立深比较通过。原始生产源码为 `e16335d6a3ee6f19c9a0bff9157172741132c93e`。长样本在 GPU 实验中使用了提前转换好的 720 秒截段，因此上述数字不能外推到完整长 M4A 的端到端吞吐，也不能作为消除 GPU 低谷的保证。每方案只有 3 次，未宣称统计显著性。

独立 CPU 测试的完整 8849.899 秒长音频中，原混音单项中位数为 8.176 秒，直接相加为 0.991 秒，节省 7.185 秒。原整段准备中位数为 19.050 秒。该单项差值约占原准备时间的 37.7%，不是整个 ASR 的加速比例。先前实验相加分支未处理负零按位差异；正式实现补上该边界，下面另行测量正式实现的成本。

原始两轮实验、失败和恢复证据保留于操作目录 `/root/autodl-tmp/production-ops/gpu-validation-20261011-1129/` 和 `gpu-validation-20261011-1144/`，未作为项目运行依赖。此次额外 CPU 复测的 SSH 上传连接被拒绝，未启动远端候选测试、也未修改生产源码。

## 正式实现的可复现 CPU 基准

执行：

```shell
python scripts/benchmark_asr_mixing.py --frames 100000 1000000 8000000 --repeats 3
```

脚本不加载模型，以固定随机种子的 float32 双声道数组交替测试原路径与正式实现；创建输入及按位比较不计入混音计时。计时包含正式实现的正零处理。2026-10-11 在本地 Windows、Python 3.12.10、NumPy 2.5.1 上的结果：

| 帧数 | 输入大小 | 原 mean 中位数 | 正式实现中位数 | 混音单项加速 |
|---:|---:|---:|---:|---:|
| 100,000 | 0.8 MB | 0.719 ms | 0.055 ms | 13.08× |
| 1,000,000 | 8 MB | 8.083 ms | 1.376 ms | 5.88× |
| 8,000,000 | 64 MB | 67.336 ms | 12.608 ms | 5.34× |

这是合成输入的 CPU 微基准，不能代表生产整任务或 GPU 吞吐。[机器可读结果](asr-stereo-mix-implementation-2026-10-11.json)包含每次计时、环境和实现文件 SHA-256。文件哈希针对测量时的源文件字节，跨平台换行转换会改变哈希。

## 验证

新增 30 个用例比较原路径和正式实现的 float32 位模式，覆盖负零、subnormal、溢出、NaN/Infinity、空数组、单帧、不同 dtype、其他声道数、非连续及只读输入，并检查原输入不被修改。runner 集成测试核对 16k、44.1k、48k 输入到 processor 的完整波形，分块测试核对块内容、覆盖长度和偏移。

ASR 定向回归共 172 项通过、1 项跳过，包含原有 Qwen runner、两遍波形复用、预取、批处理、质量及 facade 测试。两项变异验证分别把声道判断改错、移除正零处理；新增测试均捕获错误，恢复源码后全部通过。Ruff E9 与源码/测试/脚本编译检查通过。

wheel 构建通过，并检查 wheel 内包含正式混音函数和 runner 调用。首次全量 Windows 检查结果为 2984 passed、34 failed、82 skipped、12 errors，不能称全量绿色。安装入口错误来自未准备离线 wheelhouse；其余环境问题包括子进程导入旧 checkout、默认 GBK 读取 UTF-8 文件、符号链接权限、ROCm 平台假设、Windows 文件锁及覆盖率路径分隔符。

补齐临时测试依赖、设置当前分支 `src` 的 PYTHONPATH 和 PYTHONUTF8 后，安装入口重跑 13 passed，契约/历史导入/出版 CLI 重跑 83 passed、2 skipped，工作流问题回归重跑 10 passed、1 skipped，源补充/通用出版/测试基础设施重跑 51 passed、2 failed。这两项基础设施失败以及其他持续的平台失败均在未修改的 `608aeab` 基线中复现，合计 13 个不同的 Windows 平台用例；未为这次混音优化修改它们。新增及 ASR 相关用例未失败。上述重跑用于确认失败来源，没有再把全量测试汇总成一个全通过数字。

额外尝试安装 NumPy 1.26 的验证环境时下载没有完成，已终止该下载；此分支数值测试和性能基准只确认本地 NumPy 2.5.1，未宣称跨版本测量。先前生产真实音频实验结果也不能替代正式实现的跨平台检查。

合并后的实际收益仍应以生产共同墙钟、完整音频准备和输出等价性检查验收。当前分支的验证不等于已部署，也不意味着 GPU 低谷全部消失。
