# B 站分页恢复与必要请求重试

对应 [#305](https://github.com/SuperCatQR/bilibili-asr-archive/issues/305) 与 [#306](https://github.com/SuperCatQR/bilibili-asr-archive/issues/306)。分支 `codex/bili-crawl-recovery` 基于 `472229804283655e877a3dd01764e4991a807cc9`，验证日期 2026-10-10（Asia/Hong_Kong）。

## 恢复完整性

隐式恢复（默认续跑或 `--resume`）在使用页码游标前，读取已有 `ingestion_pages` / `ingestion_discoveries` 的成功页面身份，再通过网关重新读取游标之前的全部列表页，核对 BVID 顺序。前缀核对只读取列表，不重复更新详情、分 P、标签或历史实体；重复 BVID 按 discovery 已有的最后位置契约比较。

仅检查最后一页无法发现前面任意范围的删除、插入或重排，因此本次选择全前缀核对。每次列表请求和固定一秒节流均受共享请求数、单请求 deadline 和运行 deadline 约束。额外成本是与前缀页数成正比的列表请求，不是一次完整的逐视频刷新。

前缀变化或缺少历史成功页时，记录 `metadata_resume_requires_reenumeration`，保留原游标并提示 `--incremental`；`--skip-failed-page` 不能跳过前缀核对失败。认证、风控、网络和数据结构错误也保留游标。此前有意跳过的页面继续保留失败证据，但缺少可核对前缀时，后续隐式恢复不能直接声明完整。

`--incremental` 从首页重新枚举，已有实体通过原 upsert 规则去重，历史归档不会因上游删除而被删除。显式 `--start-page` 仍是操作者指定的局部起点，不能据此推断完整首页覆盖。

本实现验证两次运行之间的偏移变化，无法冻结 B 站服务器列表，也不能保证核对后或单次分页过程中发生的任意变动都被捕获。持续归档仍需周期性从首页枚举；`complete` 表示该次遍历抵达空页，不是服务器快照证明。

## 必要请求恢复

新增 `--operation-retries 0..5`，默认 0，仅作用于分页采集中的必要详情与分 P 请求；`--page-retries` 仍只负责投稿列表的有限重试。定向 `--bvid` / `--refresh-failed` 明确拒绝非零 operation-retries，避免静默忽略。

必要请求只对传输错误重试，使用 30/60/120/240/300 秒的有限冷却。每次调用进入同一个 RequestScheduler，计入请求数和总耗时；等待也受共享 deadline 与风控冷却约束。`request_budget_exhausted` 立即停止，不进入重试循环。认证、确定 not-found、风控和结构错误直接返回原失败分类。

重试只重复失败的操作，已成功列表与兄弟视频请求不重做。最终耗尽沿既有页级失败事务保留游标及失败操作诊断，不提交半页。可选标签的降级、旧集合保护和刷新复用策略继续由原逻辑负责。
