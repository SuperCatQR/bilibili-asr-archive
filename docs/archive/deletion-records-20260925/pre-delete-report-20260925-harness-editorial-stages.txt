# 精校 stage: reading-edition verifier + seam/concat checks

> **For agentic workers:** REQUIRED SUB-SKILL: Use `mstar-sdd`. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Make the **polish stage** verifiable: an operator can run the **reading-edition verifier**
against a candidate (and, for multi-part items, its parts and their proofread base) and get a verdict
that refuses with named reasons when the candidate breaks the stage's rules — timestamps present,
characters outside the base and the two routes, **unexplained insertions**, an unclassified deletion, a
**hotword-table term deleted under cover of a "repeat"** (the `此在` blind spot), marker-parity breaks,
seam breaks, or a body that is not the byte-exact concatenation of its parts.

**Closes / advances:** plan 2 of 2 for the iteration direction.

**Architecture:** Same split as plan 1 — a **pure** rule module (`services/reading_verify.py`) and CLI
composition. The **base is the containment reference for the edition's characters only up to what the
routes support**: the 2026-09-23 close measured that a base can adjudicate a term as *correctly retained*
while the edition deletes it, and that the routes (not the base) are what proves the term was spoken
(D4 + the `此在` finding). The deletion classifier therefore takes **the base, the two routes, and the
term list**, classifies every deletion run into exactly one of three classes, and **refuses** a deletion
whose core characters belong to a term the base uses — even when it looks like an adjacent repeat.

**Tech Stack:** Python 3.12, stdlib (difflib), pytest. No new dependency.

**Execution:** mstar-sdd

**Main worktree branch**: `main`.

## Global Constraints

- Same two-roots / pinned-invocation / no-full-suite / fixtures-only constraints as plan 1 (restated there once; both plans carry the same block by reference to `{PLAN_DIR}/20260923-transcript-proofread.md` § Global Constraints).
- **The deletion classifier is the article under test.** Its known blind spot is documented and must be covered by a fixture: 「在此在」 was judged "adjacent repeat" and the term `此在` was lost; the identical shape must now **refuse**.
- **The measured false-positive episode is a constraint, not trivia**: a ±40-character window produced 50 false "content loss" hits and **0 real losses** (`README-reading-edition.md:82`); the shipped rule uses ≥ ±200 characters **and** a core-character check — the wave's recorded fix, `±200 字窗口检验`, e.g. `.tmp/proofread-work/reading/BV1vNTqzFEve.p0.p3.notes.md`. The plan's fixtures include that shape.
- **Do not edit:** `{KNOWLEDGE_DIR}/**`, `{HARNESS_DIR}/workflows/**`, `status.json`, the register, other plans. Docs limited to the files the tasks name.
- **Corpus placement (compass D12): path-referenced, never copied into the repo.** Parts + merged editions are read where they are delivered — `/mnt/123pan/bili-asr-e2e/proofread-transcripts/reading/` and `.tmp/proofread-work/{reading,reading-merged,fixed}/` (all six merged editions verified byte-identical to the delivered `reading/` tree by sha256) — with the two route sources at `/mnt/123pan/bili-asr-e2e/asr-vs-subtitle/transcripts/raw/` (ASR) and `/mnt/123pan/bili-asr-e2e/subtitle-publish/transcripts/raw/` (caption). ## Operator surface (product — compass D11)

Fixed so no task re-opens it; the full decision, its rationale and the rejected alternatives are compass
**D11**. Everything below is the operator-facing contract of the new command.

```text
bili-asr verify-reading-edition --candidate <path> --bvid <bvid[:pN]> --base <path>
                                [--part <path>]… [--archive-root <root>]
```

- **Selector is required**: `--bvid <bvid[:pN]>` names the part whose routes the candidate is checked
  against, following the shipped `_subtitle_selector` rule (`cli.py:838-857`: bare `bvid` = every stored
  part of that video, `bvid:pN` = exactly that part). An unknown selector is the configuration error
  `verify-reading-edition: unknown --bvid <value>`, exit 1 (the shipped line form, `cli.py:1046`/`:1141`/
  `:1400`); a candidate whose frontmatter `work_id`/`bvid` disagrees with the selector is refused by name
  (the `identity_mismatch` discipline `coverage --quality` uses).
- **Accepts a single merged file or a part list + base.** `--candidate` is the edition under test (one
  merged file, or a single-part edition); `--base` is its proofread base; `--part` is repeatable and names
  the parts of a multi-part candidate. `--part` is **required exactly when the candidate declares more
  than one part** and refused by name when it contradicts the declaration — a conditional flag, not an
  accepted-but-ignored one (the README's own rule, `README.md:373-381`). Unreadable inputs are exit 1 with
  the path named, never a traceback.
- **Prints** — one line per candidate, then the closing counts line carrying every count including the
  zeros (`derive-manifest`'s shipped form):
  - `<work_id>: ok (body_chars=<n> base_chars=<n> deletions=<n> classified=<n> marks=<n> parts=<n>)` —
    `base_chars` is printed beside `body_chars` because criterion 4's recorded numbers are **ratios**
    (`body_chars`/`base_chars`, per `README-reading-edition.md`'s table);
  - `<work_id>: refused (<rule>) at <location>` — the rule named and the location (`<path>:<line>` or a
    `[hh:mm:ss]`/cue index), never a bare failure. Criterion 3's `此在` shape (「在此在」→「在」)
    refuses under the term guard; a deletion whose core is a hotword-table term the base uses is a
    refusal, not a repeat;
  - `warning (<rule>) at <location>` — an advisory: it changes neither the verdict nor the exit (the
    shipped defect-vs-advisory split, `README.md:672-679`);
  - then `verify-reading-edition: candidates=<n> ok=<n> refused=<n>`.
  - **Three line kinds are fixed; the rule vocabulary is not** — it is the architect's refusal taxonomy
    (compass Q2 → D14).
- **Exit** — `0` when every candidate is ok, **including zero candidates** (`cli.py:1098-1100`'s
  empty-is-success precedent); `1` for a usage/configuration error (an unknown `--bvid`, a missing or
  unreadable store, an unreadable `--candidate`/`--base`/`--part`, a `--part` set contradicting the
  candidate, or a required `--part` omitted) and for a candidate the command refused; **`2` is never
  produced** (no socket is opened; `_UsageErrorArgumentParser` maps argparse's own usage exit to 1).
  No new exit value — compass D8.
- **Disclosures the operator surface must carry** (criterion 5 checks them): the command verifies bytes
  and the record — it **does not polish**; no audio was listened to; both routes are machine transcripts
  and **neither is ground truth**; a `〔?〕` site is proven *marked*, never resolved.
- **Route source (compass D13)**: the ASR route from the bundle's `raw` sidecar, the caption route from
  the store (read-only) — shared with plan 1's surface; the printed lines and exit stance above are
  unaffected.
- **Rule vocabulary** — the `refused (<rule>)` / `warning (<rule>)` rule ids are the contract's `§E` table (D14); the edition rules are `timestamp_in_body`, `insertion_unexplained`, `deletion_unclassified`, `term_guard_tripped`, `twin_not_retained`, `seam_break`, `concat_mismatch`, `marker_parity`, `part_missing`.
