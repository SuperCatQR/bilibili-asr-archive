# Runtime issue burndown verification

Date: 2026-10-06. Branch: `codex/burndown-runtime`. Plan: `.mstar/plans/20261006-open-issue-burndown.md`.

## Resolved in this change

- **#48**: Changing `--artifact-root` intentionally publishes at the requested new write base without deleting or migrating the former bundle. New archived execution/projection rows carry absolute lexical `artifact_base`, making otherwise equal root-relative publications distinguishable. Legacy rows remain unattributed; readers keep their invocation's ordered read bases. `test_changed_artifact_root_records_publication_base` checks distinct persisted rows, complete bundles at both roots, unchanged relative names, and idempotent reuse. Existing `test_publish_preserves_complete_bundle_when_its_read_is_inconclusive` checks that inconclusive reads preserve content rather than republish.
- **#104**: Archive publication checks every visible final artifact with no symlink following before invalidating completion state. `_replace_at` also rechecks the destination immediately before replacement. Windows fallback checks final artifacts and marker. `test_publication_refuses_nonregular_artifact_before_any_bundle_change` covers all four kinds, file symlinks and directories, preserving outside content, the existing marker and the other artifacts. This rejects observed nonregular targets; it does not claim exclusion of hostile concurrent filesystem replacement beyond the existing descriptor guarantees.
- **#125**: Operational guidance now agrees with existing code: one owned batch usage snapshot, candidate refresh, refusal of unmeasurable usage under finite caps, a real write/file-sync probe and POSIX directory-sync probe, and reuse of resolved roots. Existing `test_tracker_refreshes_both_candidates_without_double_counting`, `test_unmeasurable_usage_refuses_downloads_with_a_finite_cap`, `test_probe_refuses_unwritable_or_unsyncable_roots_and_cleans_up`, `test_audio_inventory_reuses_the_invocations_resolved_roots`, and `test_schedule_plan_and_download_gate_share_one_owned_snapshot` cover the requested boundaries. Both audio-retention-policy qualifications were already present on baseline; artifact-root's stale fail-open statement is corrected. Filesystem calls can still block below Python.
- **#126**: Shared `usable_audio_path` / `usable_audio_for_path` return the base, declared relative path and confined path together, with the nonempty predicate and a guarded file open. Audio producer, coordinator and CLI pairings use these helpers. The CLI download branch does not independently derive/probe the returned pair twice. `test_empty_configured_stub_does_not_shadow_usable_legacy_audio` verifies configured empty stubs cannot hide valid legacy copies, including absolute-path pairing.
- **#158**: Pending commands have two documented surfaces: store acquisition gaps and publication recovery. Manifest `subtitle_done` or archived write-back-error rows may resume only when their part exists in the store and is not `gone`; stale `needs_audio` cannot resurrect a satisfied acquisition gap. `test_publication_recovery_requires_a_store_part_and_ignores_manifest_only` covers both stages plus absent/gone identities. Existing scheduler/long-live archive-through-store fixtures pass, including `test_schedule_limit_marks_limited_and_does_not_claim_corpus_complete`, `test_schedule_second_batch_completes_requested_scope_not_corpus`, `test_schedule_mixed_failure_exits_1_failed_scope_retries`, `test_schedule_risk_after_success_exits_2_and_resume_continues`, `test_schedule_pending_allow_long_live_processes_long_row`, and `test_allow_long_live_archives_and_reclaims_with_measured_peak`.
